# Reference examples (placeholder)

**Status:** planned. No example is currently approved as a verified reference.

Reference examples demonstrate the *quality and granularity* of source-backed requirements. They are not required reading for every skill invocation, and they must not be used as the hidden answers for evaluation cases.

## Planned examples
1. **C/C++ single module:** observable success/failure behavior, boundaries, and source evidence.
2. **Android Framework feature:** end-to-end cross-module trace with pinned AOSP revision and relevant build/runtime gates.
3. **Insufficient evidence:** bounded investigation, explicit unknowns, and no fabricated requirements.

## Example acceptance checklist (pending)
- [ ] Source snapshot or immutable revision is accessible.

- [ ] Build/variant assumptions and unresolved paths are explicit.
- [ ] An independent reviewer has checked accuracy and conformance using [the review protocol](../evals/REVIEW.md) before the example is marked verified.
